## 方案选型

### C端图片上传触发方式

| 方案 | 优点 | 缺点 | 决策 |
|------|------|------|------|
| A：`<input type="file">` 隐藏 + 按钮触发 | 原生，兼容性好，PC/移动均支持；移动端自动提供相机/相册选择 | 无 | **选中** |
| B：第三方上传组件（el-upload） | 功能丰富，UI 内置 | 引入 el-upload 增加包体积；已有原生方案足够 | 放弃 |

**选择理由：** 使用原生 `<input type="file" multiple accept="image/*">` + 手动调用 `/api/file/upload`，控制力更强，与现有 file.service 对接最直接。移动端 `type="file" accept="image/*"` 会自动触发相机/相册。

### 答案值存储格式

| 方案 | 格式 | 决策 |
|------|------|------|
| A：URL 字符串数组 | `['https://...url1', 'https://...url2']` | **选中** |
| B：对象数组 | `[{url: '...', key: '...'}, ...]` | 放弃 |

**选择理由：** URL 数组简单统一，与其他字符串类答案（如输入框）格式一致，数据分析展示更直接。LocalHandler 返回稳定 URL；OSS 场景下 URL 有效期通过 OSS 配置保障。

## 接口设计

**无新增接口。** 直接复用：

```
POST /api/file/upload
Content-Type: multipart/form-data

Body:
  file: <图片二进制>
  channel: 'XIAOJU_SURVEY_UPLOAD'   // 通道名，需在服务端环境变量中配置

Response:
  { code: 200, data: { url: string, key: string } }
```

调用方：C端 ImageUploadModule widget，每张图片单独上传一次，并发控制（同时最多2张）。

---

## 数据模型变更

**无 Entity 变更。**

图片答案作为 URL 字符串数组存入现有 `SurveyResponse.data` 字段（类型 `Record<string, any>`），与其他题型答案格式一致：

```json
{
  "data": {
    "data1": ["https://...img1.jpg", "https://...img2.jpg"],
    "data2": "some_text_answer"
  }
}
```

## 实现步骤概览

### Step 1：后端枚举扩展

修改 `server/src/enums/question.ts`，新增：
```ts

```
（不加入 `dataStatistic.controller.ts` 的 `allowQuestionType`，图片题不支持分题统计）

### Step 2：前端枚举扩展

修改 `web/src/common/typeEnum.ts`：
- `QUESTION_TYPE` 枚举新增 `IMAGE_UPLOAD = 'image-upload'`
- `typeTagLabels` 新增 `[QUESTION_TYPE.IMAGE_UPLOAD]: '图片上传'`
- `ADVANCED` 数组新增 `QUESTION_TYPE.IMAGE_UPLOAD`

### Step 3：新建 Widget

**`web/src/materials/questions/widgets/ImageUploadModule/meta.js`**

字段定义：
- `field`: String（题目ID）
- `title`: String（默认'标题X'）
- `type`: String（固定 'image-upload'）
- `isRequired`: Boolean（默认 true）
- `showIndex`: Boolean（默认 true）
- `showType`: Boolean（默认 false）
- `showSpliter`: Boolean（默认 true）
- `maxImageCount`: Number（默认 5，1-10）
- `maxFileSize`: Number（默认 100，1-100，单位 MB）

formConfig：
- `basicConfig`（基础配置复用 basicConfig.js）
- 自定义"上传限制"配置区（maxImageCount 下拉 + maxFileSize 输入框）

**`web/src/materials/questions/widgets/ImageUploadModule/index.jsx`**

B端预览：展示图片上传区域占位图（只读），显示"最多上传N张"提示文案。

C端交互：
- 展示上传按钮（图标 + 提示文案"最多上传N张"）
- 已达上限时隐藏按钮
- 点击按钮触发 `<input type="file" multiple accept="image/*">` 文件选择
- 文件选中后逐张校验（格式、大小）并上传至 `/api/file/upload`
- 上传中显示进度状态；允许取消中途上传（abort fetch）
- 已上传图片以缩略图展示，右上角有删除按钮
- `@change` emit 当前已上传图片 URL 数组（作为题目 value）

必填校验：通过 `QuestionRuleContainer` 的 validate 机制，value 为空数组时触发校验错误。

### Step 5：数据分析展示

**`server/src/modules/survey/services/dataStatistic.service.ts`**

在 `getDataTable` 的 listBody 构建循环中，新增 image-upload 类型处理：
```ts
if (itemConfig.type === QUESTION_TYPE.IMAGE_UPLOAD) {
  const urls = Array.isArray(data[itemKey]) ? data[itemKey] : []
  data[itemKey] = urls
    .map(url => `<img src="${url}" style="height:60px;width:60px;object-fit:cover;margin:2px;">`)
    .join('')
}
```

**`web/src/management/pages/analysis/components/DataTable.vue`**

`getContent` 当前对数组做 join(',')。由于后端已将 image-upload 字段转为 HTML 字符串，`getContent` 不需要额外处理。但需补充 CSS 让图片 3 列网格排列（在 `.table-row-cell :deep(img)` 样式区域调整，或新增 `.image-upload-gallery` 容器 class）。

## 风险与待确认项

- [ ] **文件上传 channel 名称**：C端 widget 调用 `/api/file/upload` 需要传 `channel` 参数。生产环境需配置对应渠道（如 `XIAOJU_SURVEY_UPLOAD`）。本地开发默认 LocalHandler 无需 OSS，可直接测试。需确认**正式部署用哪个 channel**。
- [ ] **图片 URL 有效期**：如生产使用七牛/OSS 私有 bucket，URL 可能有时效。当前方案存储永久 URL（LocalHandler / 公开 bucket 无问题）；若需签名 URL 需额外处理。
- [ ] **snapshot 图片**：questionMenuConfig 中的 snapshot 图片路径 `/imgs/question-type-snapshot/image-upload.webp` 需要准备一张预览图放到 `web/public/` 下，否则菜单悬浮无预览。可复用其他题型的占位图，优先级较低。
