所有 step 执行完毕后，请执行完整性自检。

## 1. Ghost Reference 扫描

在所有已生成的 harness/、work/、.claude/ 文件中搜索引用的文件路径，
检查每个被引用的文件是否真实存在。
列出所有 ghost references 并修复（创建占位文件或移除引用）。

## 2. 交叉引用一致性

检查以下引用关系是否完整一致：
- AGENTS.md 的"核心事实来源索引"是否覆盖了所有已生成的 harness/ 文件
- workflow.md 中引用的文件路径是否都存在
- skills 和 commands 中引用的文件路径是否都存在
- 角色文件中引用的 harness 文件是否都存在

如有遗漏，更新对应的索引或引用。

## 3. TODO 残留审计

列出所有残留的 `TODO: needs input`。
对每个 TODO 判断：能否从当前代码事实解决？
- 能解决的立即修复
- 不能的保留并说明原因

## 4. 冗余扫描

检查是否有内容高度重复的文件，特别是：
- references/ 下的链接索引 vs engineering/ 下的使用指南
- 多个文件中出现相同的表格或列表
- 已删除功能的残留引用

如有冗余，合并到更合适的位置并删除冗余文件。

## 5. .gitignore 检查

检查 `.gitignore` 是否已包含以下条目：
- `.claude/settings.local.json`（本机权限配置，不进版本控制）
- `work/runs/` 下的大文件（可选，视团队约定）

如缺失，提示用户补充（不自动修改 .gitignore）。

## 6. 模板对照

对照目标结构模板（fullstack.md / frontend.md / backend.md 中适用的那个），
列出每个模板要求的文件的实际状态：

| 模板要求的文件 | 状态 |
|-------------|------|
| ... | 已创建 / 已合并到 XX / 不适用（原因）/ 缺失 |

## 输出格式

```
### 完整性自检报告

**Ghost References:** N 处
- [已修复] / [需修复] 列表

**交叉引用:** 全部一致 / N 处不一致
- 列表

**TODO 残留:** N 处
- M 处已从代码事实解决
- K 处保留（原因）

**冗余:** N 处
- [已合并] / [已删除] 列表

**模板覆盖率:** X/Y 文件已覆盖
```

## 7. 持久化

将上述自检报告写入 `work/runs/harness-init-report.md`，作为本次 harness 初始化的记录。
